## 0.9.0-beta.2

Security review before the public beta (an independent review of all internet-facing parts; no critical issues):

- **Login lockout can no longer be triggered by strangers.** Failed logins lock per account *and* client IP; a name-wide
  limit (20 per hour) only applies to browsers that have never signed in to that account.
- **Client IP behind proxies:** `X-Forwarded-For` is read from the right (the entry your proxy added), `CF-Connecting-IP`
  is only trusted from the stack's cloudflared or `PROXY_IPS`.
- **Direct-access tokens split:** the token in media URLs (`?st=`) only opens music, images and exports; the API token is
  header-only and never opens administration (admin calls always use the normal address and session).
- **Password-reset links** never use a foreign `Host` header (without `APP_URL` the address the admin last signed in with
  is used). A password reset signs out all devices and revokes app keys; so does an admin setting a new password.
- **Update upload and restore need the admin password.**
- **Setup always asks for the setup code** (the link in the log contains it) – `EINRICHTUNG_CODE_IMMER=0` restores the old
  behaviour on the home network.
- Logs mask API keys, tokens and passwords. MusicBrainz & Co. now see the project URL as contact instead of a personal address.

Windows client:
- **Installer:** installs for the current user without admin rights (`%LOCALAPPDATA%\Programs\Amberwave`), Start menu entry,
  uninstall via Settings → Apps (settings can be kept). `/portabel` unpacks next to the package as before.
- **Update notice** in the tray menu when GitHub has a newer release, **compatibility check** with the server
  (`client_protokoll` in `/api/v1/ping`), **About** dialog with licenses.

Also: Cloudflare terms notice in the tunnel setup, Unraid guide (Docker Compose Manager), genre families were recalculated
every minute because of a missing setting (fixed).

## 0.9.0-beta.1 (first public beta)

Server and Windows client now share one version number.

- **Music folder is read-only by default.** New installations only read your collection. Writing (tags, tidy-up,
  download import, “take track from another album”, trash) must be allowed in the setup assistant or under
  Settings → Library & automation → Music folder (`MUSIK_SCHREIBEN=1`). Every write path checks this, including a second check in the
  low-level file writers. Existing installations keep writing allowed.
- **Usenet downloads are off by default.** Switch on under Settings → Downloads (`USENET_AKTIV=1`). When off there is no
  downloads area, no search and nothing is fetched. Existing installations with Prowlarr/SABnzbd set up keep it on.
- **Ready-made Docker image** (`ghcr.io/<owner>/amberwave`, built by GitHub Actions on every release tag) with a short
  `docker-compose.yml` and a `.env.example` of five lines. The previous self-build setup is `docker-compose.build.yml`;
  every option is documented in `.env.reference`.
- **Update notice:** the admin overview shows when a newer release exists on GitHub (twice a day, nothing is downloaded;
  switch off under Settings → Backup & update). Image installations update with `docker compose pull`.
- **Licensing:** AGPL-3.0 for the core, third-party notices, contribution guide with CLA, security policy, issue templates.
- English README; German guide in `README.de.md`.

## Before the beta (0.1 – 0.2.178)

The development history before the beta is kept in German below (it used to be part of the README).

### Was v0.1 kann

- **Konten** wie im Bücher-Archiv: Registrierung mit Freischaltung (1–24 Monate), Verlängern, Sperren, Ablauf-Erinnerung,
  Login-Sperre bei Fehlversuchen, „Gerät merken“, Geräte-Begrenzung, Passwort vergessen, E-Mail über web.de.
- **Ein Ordner = ein Album**, solange der Albumtitel gleich ist – auch wenn einzelnen Dateien der Albuminterpret fehlt
  (früher wurden sie als unsichtbare Zweit-Edition abgespalten). Dateien ohne Gegenstück in einer abgeglichenen Edition
  (Bonustitel, Demos) erscheinen als zusätzliche Titel. Unter Verwaltung → Bibliothek → Auffälligkeiten stehen Dateien,
  die nur in nicht angezeigten Editionen stecken.
- **Einlesen** ohne Rückfragen: FLAC, MP3, M4A/ALAC, Opus, OGG, WAV, AIFF, WavPack u. a.; CD1/CD2-Unterordner,
  Sampler, Mehrfach-Künstler aus den Tags (ARTISTS), Cover aus dem Ordner oder der Datei, ReplayGain, inkrementell.
- **MusicBrainz-Abgleich**: alle Editionen eines Albums (nicht nur die ersten Treffer), Filter nach Land/Format/Titelanzahl,
  Vergleich „deine Datei ↔ MusicBrainz“ Zeile für Zeile, Übernahme von Album, Edition, Titeln, Künstler-Credits,
  Label, Genres, Produzenten, Musikern mit Instrumenten, Songwritern (über Kompositionen), Technik; Bandmitglieder.
  Gesperrte Felder bleiben unangetastet.
- **Bearbeiten direkt in der Bibliothek** (nur Admin): Knopf „Bearbeiten“ auf der Albumseite (am Handy im Menü ⋯) für Album,
  Titelliste (Titel, CD- und Titelnummern; neue CD-Nummer = neue CD, doppelte Belegung wird abgelehnt), Mitwirkende,
  Edition, Cover und Albumkünstler; „Titel bearbeiten …“ im Menü ⋯ jedes Titels (Name, CD und Nummer,
  eigene Künstler wie „feat.“ – der Gast erscheint dann auch auf seiner Künstlerseite); „Bearbeiten“ auf jeder Künstlerseite.
  Von Hand Geändertes wird automatisch vor Scan und MusicBrainz geschützt.
- **Alben „Nach Künstler“ gruppiert** (Umschalter oben rechts, mit A–Z-Leiste) und **Künstler sortierbar**
  (Name A–Z/Z–A, meiste Alben, zuletzt hinzugefügt, von dir am meisten gehört, Zufall; Filter Personen/Bands).
- **Familie sieht eine Edition pro Album** (die mit den meisten Titeln, bei Gleichstand die neueste; von dir änderbar).
- **Oberfläche** im Glas-Design mit Bernstein-Akzent: Start (Weiterhören, Neu, Oft gehört, Entdecken), Alben mit Filtern,
  Albumseite mit Mitwirkenden, Künstler- und Personenseiten (Als Produzent / Musiker / Songwriter, häufige Partner, Besetzung),
  Suche, Playlists (auch für die Familie geteilt), Gemerkt, Verlauf, Profil. Feste Layouts für Desktop, Tablet und Handy
  (Tab-Leiste unten).
- **Player** ohne Unterbrechung beim Navigieren. „Läuft gerade“ im Layout „Bühne“: am Desktop Cover mittig im Bild, Mitwirkende links, Als Nächstes rechts,
  unten Signalweg | Steuerung (mittig) | Qualität + Lautstärke – alles ohne Scrollen. Am Handy nur der Player,
  Als Nächstes / Mitwirkende / Technik in einem Blatt von unten,
  Sperrbildschirm-Steuerung. Lautstärke-Angleich nach EBU R128 (siehe unten). Streaming als Original oder live umgewandelt (Opus 256/160/128, AAC als Ausweich).
- **API-first**: Die Oberfläche nutzt ausschließlich `/api/v1`. Der spätere Windows-Player meldet sich per Geräte-Schlüssel an
  und bekommt die Dateien bitgenau (siehe `docs/API.md`).

- **Künstlerbilder von fanart.tv**: Schlüssel unter Einstellungen eintragen, dann holt die App die Bilder im Hintergrund
  (alle `FANART_ALLE_MINUTEN`, Standard 10) oder sofort über Verwaltung → Bibliothek → „Jetzt holen“. Künstler ohne
  MusicBrainz-ID werden vorher eindeutig gesucht; eigene hochgeladene Bilder bleiben.
- **Namen immer „Vorname Nachname“**: „Jackson, Michael“ aus den Tags wird zu „Michael Jackson“
  – doppelte Künstler werden dabei zusammengeführt. Bandnamen wie „Earth, Wind & Fire“ bleiben.
  Auch sortiert wird nach Vorname Nachname („Michael Jackson“ unter M); ein Artikel am Anfang zählt nicht
  („The Beatles“ unter B, abschaltbar mit `SORTIERUNG_OHNE_ARTIKEL=0`).

- **Qualität zuhause / unterwegs, pro Gerät gemerkt**: Im Heimnetz (direkt im LAN oder über den Tunnel mit der eigenen
  öffentlichen Adresse) spielt „Automatisch“ die Originaldatei, sofern der Browser sie kann. Unterwegs: Handy/Tablet
  (per Browserkennung) Opus 160, im Mobilfunk oder mit Datensparen Opus 128, sonst Opus 256. Beide Einstellungen
  liegen pro Gerät auf dem Server; ein Netzwechsel gilt ab dem nächsten Titel.

- **Robuster Scanner**: Ordner/Dateien ohne Leserecht werden gemeldet (Verwaltung → Bibliothek) statt still übersprungen,
  und was davon schon eingelesen war, bleibt erhalten. Ist der Musikordner leer (Array gestoppt, Mount fehlt), wird
  nichts gelöscht. Die App läuft als `PUID`/`PGID` (Unraid: 99/100 wie Lidarr) und liest damit alles, was Lidarr anlegt.

- **Künstlerseite: Genres und beliebteste Titel**: Genre-Badges aus MusicBrainz (die stärksten fünf nach Stimmen, sonst die
  häufigsten Genres seiner Alben in der Sammlung; Klick zeigt alle Alben des Genres). Darunter die **Top 10 weltweit** nach
  Hörern bei ListenBrainz (offene Statistik von MetaBrainz, ohne Schlüssel, alle `BELIEBT_TAGE` neu geholt) – zugeordnet
  über die MusicBrainz-Aufnahme, sonst über den Titel ohne Zusätze wie „Remaster“; gespielt wird die Fassung vom
  Studioalbum. **Fehlende Titel bleiben in der Liste**, gedimmt mit dem Album, auf dem sie erschienen sind, und einer
  Zusammenfassung („6 der Top 10 fehlen dir – zu finden auf: Bad (2), …“). Umschalter **Bei uns**: die meistgehörten Titel
  aller Familienmitglieder. „Vorhandene abspielen“ spielt nur, was da ist.

- **Dateien aufräumen** (Verwaltung → Bibliothek oder Album-Menü „Dateien aufräumen …“, nur abgeglichene Alben):
  schreibt die Daten aus Amberwave in die Dateien – FLAC (Vorbis-Kommentar), MP3 (ID3v2.4) und M4A (iTunes-Felder) mit
  den Feldnamen von MusicBrainz Picard: Titel, Interpreten einzeln und als Anzeigetext, mehrere Albuminterpreten,
  Edition (Label, Katalognummer, Barcode, Land, Medium, Datum/Erstveröffentlichung, Versionsname), Genres, Komponist,
  Texter, Produzent, Mix, Toningenieur, Musiker mit Instrument, Werk, alle MusicBrainz-IDs und ReplayGain aus der eigenen
  Lautheitsmessung – dazu das Cover. Alte und fremde Tags werden dabei bereinigt (`AUFRAEUMEN_TAGS=sauber`); es bleiben
  nur `AUFRAEUMEN_BEHALTEN` (Liedtexte, ISRC) und Technisches für lückenlose Wiedergabe (iTunSMPB). Die Vorschau zeigt
  je Feld bisher → neu bzw. „wird entfernt“. Es passiert nie etwas von selbst:
  erst die Vorschau, dann deine Freigabe (je Album oder alle auf einmal). Umbenannt und getaggt wird an Ort und Stelle im
  Wurzelordner der Bibliothek, z. B. `Bruno Mars/2012 - Unorthodox Jukebox/01 - …` (Altes kommt in den Papierkorb).
  Das Audio wird nie angefasst: Passt alles in den vorhandenen Kopf (Füllblock), wird nur der überschrieben, sonst wird
  die Datei daneben neu zusammengesetzt; vorher und nachher wird über die dekodierten Audiodaten eine Prüfsumme gebildet –
  weichen sie ab, bleibt die Datei, wie sie war. Außerdem: Ordner und Dateien nach Schema benennen
  (`AUFRAEUMEN_ORDNER`, `AUFRAEUMEN_DATEI`, Standard `Albumkünstler/Jahr der Edition - Album (Edition)/01 - Titel`, bei mehreren CDs `…/CD 2/01 - Titel`
  (`AUFRAEUMEN_CD_IMMER=1`: CD-Ordner auch bei nur einer CD);
  Disc-Nummern von MusicBrainz, auch bei nur einer CD; Namen sind Windows-/SMB-sicher, `AUFRAEUMEN_ZEICHEN=ascii` streng ASCII; Booklets & Co. wandern mit) und Müll (.nfo, .sfv, .m3u, .log, .cue,
  Thumbs.db …) entfernen. **Immer erst Vorschau** (je Album: neue Namen, Tag-Änderungen Feld für Feld, Hinweise wie
  fehlende Schreibrechte oder Ordner, die auch andere Alben enthalten), ausgeführt wird nur Freigegebenes, im Hintergrund
  und nie gleichzeitig mit dem Einlesen. Gelöschtes und die alten Tags (als JSON je Datei) landen im Ordner
  `.amberwave-papierkorb` im Musikordner und werden nach `AUFRAEUMEN_PAPIERKORB_TAGE` (30) gelöscht. Die Datenbank wird
  direkt nachgezogen (Pfade, Größen, Tags) – kein neues Einlesen nötig, Wiedergabe läuft weiter.

- **Alben am Klang erkennen** (Verwaltung → Bibliothek): Jeder Titel bekommt einen akustischen Fingerabdruck
  (Chromaprint über das vorhandene ffmpeg, die ersten 120 s, niedrige Priorität), AcoustID nennt dazu die MusicBrainz-Aufnahme.
  Je Albumordner werden die Releases geladen, die (fast) alle Titel enthalten, und Titel für Titel verglichen – Aufnahme,
  Reihenfolge, Anzahl, Laufzeiten → Sicherheit in %. Eindeutiges wird automatisch übernommen (wie „Diese Edition übernehmen“,
  vorhandenes Cover bleibt). Gibt es dieselbe Titelliste auf mehreren Editionen, entscheiden MusicBrainz-ID oder Barcode aus
  den Tags, dann die Laufzeiten, sonst Regeln: offiziell, Format passend zu den Dateien (CD bzw. bei Hi-Res Digital), Land
  (DE, Europa, weltweit …), frühestes Datum – diese Alben stehen zum Prüfen in der Liste, mit allen geprüften Editionen zum
  Vergleichen und Umstellen. Nur noch nicht abgeglichene Alben werden angefasst, an den Dateien ändert sich nichts.
  Braucht einen kostenlosen AcoustID-Schlüssel (Einstellungen oder `ACOUSTID_API_KEY`); `ERKENNUNG_AUTO=regeln|eindeutig|aus`,
  `ERKENNUNG_SCHWELLE` (90 %), `ERKENNUNG_PARALLEL`. Läuft im Hintergrund (AcoustID ≤ 3, MusicBrainz 1 Anfrage je Sekunde).

- **Editionen als eigene Alben**: Pro Album unter ⋯ → „Editionen anzeigen …“ einstellbar – dann stehen z. B. Original
  und Remaster nebeneinander in allen Listen (mit kleinem Versions-Etikett), ohne Umschalten.
- **Oberfläche**: eigene Auswahlfelder im App-Stil (am Handy mit der Systemauswahl), Zurück-Knopf zwischen Logo und Navigation,
  Play-Knopf unten rechts auf dem Cover, Künstlerseite nach Art gruppiert (Alben, EPs, Singles, Live, Kompilationen …).

- **Lückenlose Wiedergabe (gapless)** für Live- und Konzeptalben, auf das Sample genau: Zuhause wird jeder Titel als
  FLAC übertragen (FLAC-Dateien bitgenau, andere Formate verlustfrei dekodiert) und nahtlos angesetzt; unterwegs werden
  aufeinanderfolgende Titel eines Albums als ein durchgehender Opus-Strom kodiert. Die Dateien bleiben unverändert.
  Abschaltbar unter Profil & Wiedergabe; Browser ohne Media Source Extensions nutzen automatisch den klassischen Weg.
  Kann ein Browser FLAC nicht im Strom (z. B. Chrome auf Android) oder stört der FLAC-Weg, läuft „Original“ dort lückenlos
  als Opus 256 weiter statt mit Pausen (umschaltbar unter Profil & Wiedergabe, mit Diagnose der Möglichkeiten des Geräts).
  Wechselt das Format zwischen zwei Titeln (Abtastrate, Kanäle oder Bittiefe, z. B. 44,1 kHz/16 Bit → 48 kHz/24 Bit),
  beginnt ein frischer Puffer – an dieser Stelle gibt es eine winzige Lücke, dafür keine Störgeräusche durch einen
  Formatwechsel mitten im Media-Source-Puffer.
- **Raumklang (Upmix Stereo → 5.1/Quadro)**, nur an einem Mehrkanal-Ausgang (z. B. PC per HDMI am AV-Receiver, in Windows
  auf 5.1 gestellt; am Receiver Mehrkanal-PCM direkt wiedergeben). Vorne bleibt L/R bitgenau unverändert; nach hinten geht
  pro Frequenzband nur, was zwischen L und R unkorreliert ist (Hall, Raum, Publikum) – Stimmen und gepannte Instrumente
  bleiben vorne. Hinten: kein Bass (Hochpass), weniger Tiefmitten, etwas dunkler, Anschläge mit Vorausschau gedämpft,
  Ducking durch die Front, frühe Reflexionen mit verschiedenen Laufzeiten und ein dunkler Raumhall, den auch der
  Direktschall (ohne Bass) leicht anregt – damit bekommen auch trockene Aufnahmen Raum. Presets **Dezent, Raum, Halle, Live** unter
  Profil & Wiedergabe oder im Menü ⋯ von „Läuft gerade“; **Taste U** schaltet beim Hören zwischen Aus und dem Preset um
  (A/B). Zum Probehören in der DAW: ⋯ → „Titel als 5.1-WAV exportieren“ (alle vier Presets, 24 Bit, L R C LFE Ls Rs).
  **Echte Räume für den Hall:** Unter Verwaltung → System lädt der Server auf Knopfdruck das kostenlose Paket
  „IM Reverbs“ von Voxengo (Musikvereinssaal, Scala Mailand, Salon …; © Aleksey Vaneev, wird nicht mit Amberwave
  ausgeliefert, Adresse über `RAUMKLANG_IR_URL`), eigene WAV-Impulsantworten lassen sich hochladen. Die Presets wählen
  automatisch einen passenden Raum, im Profil lässt sich pro Gerät ein bestimmter wählen. Bei Pause/Stopp blenden
  Surrounds und Hall sofort mit aus. **Intensität** (Raum/Hall: Hall ±12 dB, frühe Reflexionen ±6 dB) und **Surround-Pegel**
  (Ls/Rs ±12 dB) lassen sich pro Gerät fein einstellen – die Mitte ist jeweils das Preset (Profil oder Surround-Menü).
  **Center und Bassmanagement** (ab 0.1.118): Die Front wird per M/S zu L/C/R dekodiert (Center-Anteil 0–100 %, Mitte =
  klassische Matrix: Center bekommt M mit 0 dB, die Front behält M mit −3 dB). Bass unter der Trennfrequenz (80/100/120 Hz,
  Linkwitz-Riley 24 dB/Okt.) geht aus L/C/R in den LFE (um −10 dB abgesenkt, weil der Receiver den LFE um 10 dB anhebt; oder 0 dB).
  Vorgaben `RAUMKLANG_CENTER_ANTEIL`, `RAUMKLANG_LFE_TRENNUNG`, `RAUMKLANG_LFE_PEGEL`. Das Raumklang-Modul startet bei jeder Titelwahl,
  jedem Skip und jedem Play frisch (`RAUMKLANG_NEUSTART=0` schaltet das ab); der Dialog „Raumklang fein einstellen“ zeigt, welche Fassung läuft.

- **Pegelanzeige** in der Player-Leiste und in „Läuft gerade“: kleine Spitzenpegel-Meter in dBFS (vor der Lautstärke),
  2 Kanäle, mit aktivem Raumklang 5.1 (L R | C LFE | Ls Rs) bzw. Quadro; Rücklauf 20 dB/s, Spitzenhalter 1,5 s, rot ab
  0 dBFS. Läuft über Web Audio (die Lautstärke sitzt dann hinter der Messung) – am Desktop an, an Handy/Tablet aus,
  abschaltbar unter Profil & Wiedergabe. Lückenlos bleibt auch über diesen Weg sample-genau.

- **Equalizer** (pro Gerät gemerkt): Low- und High-Shelf und zwei Glocken, alle vollparametrisch (Frequenz stufenlos,
  Pegel ±15 dB, Güte – bei den Shelves die Steilheit), dazu ein Gain-Regler (−24 … +12 dB) oder „Auto“ (senkt so weit
  ab, wie die Kurve anhebt – kann nicht übersteuern). Die Kurve zeigt das Ergebnis inklusive Gain; Punkte lassen sich
  ziehen (Mausrad = Güte, Doppelklick = 0 dB). Filter: „matched“ Biquads (Ansatz nach Vicanek) statt RBJ-Kochbuch –
  folgen dem analogen Vorbild bis nahe Nyquist, ohne das übliche Zusammenstauchen über 10 kHz; gerechnet in einem
  eigenen Worklet in doppelter Genauigkeit, Änderungen werden ohne Knacken übergeblendet. Wirkt bei Raumklang auf alle
  Kanäle und sitzt vor der Pegelanzeige.
- **Navigation merkt sich den Weg**: Wer über „Künstler“ zu einem Album kommt, bleibt im Reiter „Künstler“ (auch bei
  Zurück/Vor und nach dem Neuladen). Der Zurück-Knopf sitzt zwischen Logo und Navigation.
- **Albumseite**: Name der Edition hinter dem Titel (z. B. „Thriller Deluxe Edition“), beim Label nur der Verlag.
- **Scrollposition und Einstellungen pro Gerät**: Nach „Zurück“ und nach dem Bearbeiten (OK) bleiben Listen an ihrer Stelle –
  auch wenn schon mehrmals „Weitere laden“ gedrückt wurde (Alben, Künstler, Verwaltung → Bibliothek). Sortierungen und
  Filter merkt sich jedes Gerät selbst: Alben (Sortierung, Ansicht), Künstler (Sortierung, Art, „Mitwirkende ohne eigenes
  Album“), Verwaltung (Konten- und Bibliotheksfilter). Auf dem Handy entfallen bei den Künstlern die A–Z-Leiste und die
  Mitwirkenden ohne eigenes Album.
- **Genres von MusicBrainz**: Kommen aus Release Group und Release zusammen (Stimmen addiert); fehlen sie dort, wird die Release Group
  gezielt abgefragt. Bereits abgeglichene Alben bekommen sie beim nächsten „Neu abgleichen“. Die Albumseite zeigt im Kopf kein
  „Diese Edition: Datum (Land)“ mehr.
- **Cover beim MusicBrainz-Abgleich**: In der Trefferliste steht vor jeder Edition ihr Cover von MusicBrainz (Cover Art Archive);
  im Vergleich liegen „Dein Cover“ und „Cover bei MusicBrainz“ nebeneinander. Die Bilder laufen über den Server und werden
  zwischengespeichert (`COVERART_URL` nur nötig für einen eigenen Spiegel).
- **EQ und Raumklang in der Player-Leiste** (PC): eigene Knöpfe als Gruppe neben der Qualität, gleich hoch; aktiv = gefüllt, der
  Raumklang-Knopf nennt das Preset. Bei schmaler Leiste bleiben nur die Symbole (Play/Pause bleibt mittig). Der Raumklang-Knopf
  öffnet ein Menü mit Schalter, Presets (mit Symbolen), Raum (Impulsantwort), Reglern für Intensität, Surround-Pegel, Effekte/Breite
  nach hinten und Center-Anteil, Bassmanagement (Bass → LFE, LFE-Pegel), Solo, Abhören und Zurücksetzen (Doppelklick auf einen Regler setzt ihn zurück; Esc schließt, Taste U schaltet um).
  An einem Stereo-Ausgang zeigt das Menü einen Hinweis; die Regler lassen sich trotzdem vorbereiten.
- **Themenradios** (0.1.108): Unter „Mein Radio“ auf der Startseite Knöpfe für Jahrzehnte (70er, 80er, 90er …) und die häufigsten Genres – nur Themen mit genug Songs (`RADIO_THEMA_MIN`, Standard 25). Gespielt wird nur, was zum Thema passt (Jahrzehnt der Erstveröffentlichung; Genre von Album, Track oder Künstler), ausgewählt wie im lernenden Radio: deine Lieblinge aus dem Thema als Saat, Klangähnlichkeit, Abwechslung, jeder 4. Titel neu für dich.
- **Tägliche Datensicherung** (0.1.109): Jede Nacht (Standard 2 Uhr, also vor dem Nachtlauf) wird die Datenbank nach `<Backup-Ordner>/datenbank` gesichert. Aufbewahrt werden die letzten 7 täglichen und zusätzlich je Woche die letzte für weitere 4 Wochen (`SICHERUNG_STUNDE`, `SICHERUNG_TAGE`, `SICHERUNG_WOCHEN`, auch unter Verwaltung → System änderbar). Dort außerdem: „Jetzt sichern“ (bleibt, bis du sie löschst), Herunterladen und **Wiederherstellen**: Die Sicherung wird erst vollständig geprüft, dann wird der aktuelle Stand automatisch gesichert („Vor Wiederherstellung“, die letzten 3 bleiben), laufende Aufträge pausieren, und schlägt das Einspielen fehl, wird der vorherige Stand sofort zurückgespielt. Eine ältere Sicherung wird danach automatisch auf die aktuelle Version gebracht. Bestätigt wird durch Eintippen von WIEDERHERSTELLEN. Auch die Sicherung vor dem letzten Update lässt sich so zurückspielen. Musik und Cover sind nicht Teil der Sicherung.
- **Raumklang ohne Klingeln** (0.1.110): Die Raum-Ebene des Upmixers entschied bisher je Frequenzlinie (1025 Linien, 30 ms), was nach hinten darf. Eine so zerklüftete, flackernde Maske erzeugt im 46-ms-Fenster Vorechos und „Musical Noise“ (wässriges Klingeln, metallische Fahnen).   Lautheitsumfang LRA, Sample- und True-Peak) und speichert die Lautheit aller 400-ms-Blöcke als Histogramm. Daraus wird
  jedes Album **exakt am Stück** berechnet (Gating über alle Blöcke aller Titel, nicht der Mittelwert der Titel).
  Beim Abspielen: Titel, die im Album direkt aufeinander folgen, bekommen alle denselben **Album-Gain** – auch zwei
  aufeinanderfolgende Albumtitel in einer Playlist –, alles andere den **Titel-Gain**. Zielwert pro Gerät (Standard
  −16 LUFS, `LAUTHEIT_ZIEL`), angehoben wird nur bis −1 dBTP True-Peak (`LAUTHEIT_DECKE`), kein Limiter, keine Kompression.
  Bei Opus/AAC rechnet der Server den Gain vor dem Kodieren ein (in lückenlosen Ketten sample-genau je Titel), bei
  Original über Web Audio (an der Titelgrenze vorgeplant) bzw. ohne Web Audio über die Lautstärke (dann nur Absenken).

#### Direktzugang einrichten

1. Im Compose-File beim Dienst `app` unter `ports:` eine zweite Zeile ergänzen: `- "${APP_BIND:-0.0.0.0}:${LOKAL_HTTPS_PORT:-8443}:8443"`
   (ein eigener Port neben dem App-Port, z. B. 9950 für die App und 8443 für den Direktzugang)
   (nur im Heimnetz – im Router wird nichts freigegeben). `APP_URL` muss in der .env gesetzt sein. Update einspielen
   und den Stack einmal neu starten (das Startskript schaltet HTTPS im Container ein).
2. Bei Cloudflare unter Mein Profil → API-Token ein Token mit der Vorlage „Zone-DNS bearbeiten“ für deine Domain anlegen.
3. Verwaltung → System → „Direktzugang im Heimnetz“: Token eintragen, Name (Vorschlag `lokal.<deine App-Adresse>`)
   und die IP des Unraid im Heimnetz prüfen, „Einrichten“. Danach die Seite einmal neu laden.
4. Chrome fragt beim ersten Mal ggf., ob die Seite auf Geräte im lokalen Netzwerk zugreifen darf – erlauben.
   Hat der Router einen DNS-Rebind-Schutz, den Namen dort als Ausnahme eintragen.

Klappt es nicht, zeigt „Von diesem Gerät prüfen“ die Ursache: Seite noch nicht neu geladen, Netz/DNS/Port/Zertifikat,
`APP_URL` passt nicht zur aufgerufenen Adresse oder Chrome blockiert den Zugriff aufs lokale Netzwerk. Die Direktadresse
funktioniert auch, wenn die App im Heimnetz über die Server-IP (z. B. `http://192.168.1.10:9950`) geöffnet wird.

Wer lieber einen eigenen Reverse Proxy benutzt: `DIREKT_URL=https://…` in der .env setzt die Direktadresse fest
(ohne Zertifikats-Automatik).
