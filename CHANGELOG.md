## 0.9.1-beta.3 – effects

- **Saturation focus** for AmberGlow, AmberIron and AmberSilk: a small button next to HQ and Δ opens a curve with five
  points (low shelf, three bells, high shelf) over the live spectrum. Raise a point and the effect saturates more there –
  an EQ in front of the effect, the exact opposite behind it, so the tone stays neutral and only the distortion moves.
  "De-emphasis" 0–100 % sets how much of the boost is taken back (less = part of the boost stays, like an enhancer).
- **Drive up to 150 %** on all three effects, to overdo it on purpose (automatic level compensation stays on).
- **AmberSilk: no more aliasing at high frequencies.** The tape curve now always runs at 8× oversampling (4× from
  88.2 kHz, 192 kHz included). Worst case (7.5 ips, high drive, loud treble) improved from −46 dB to −71 dB, typical
  settings are below −90 dB; at 192 kHz the audible-band aliasing went from −48 dB to −101 dB. Frequency response
  unchanged (±0.05 dB). Costs about 4 % more CPU of one core at 44.1 kHz.
- AmberSilk: the slow-signal path of the tape curve uses the exact function (a tiny −70 dB step at heavy saturation is gone).
- **Browser effects now run as WebAssembly** – the same C code as the Windows client instead of a separate JavaScript
  copy (tested sample by sample: −170 dB difference). Silk 2× and Iron 1.6× faster in the browser. Browsers without
  WebAssembly fall back to the old JavaScript version (without the new features).

Security test (two independent testers attacking the app: anonymous from the internet, and as a normal family member):
no way in, no admin rights for normal users, no access to other users' data. Fixed what they found:

- **Password reset and all notification mails were broken** (registration notice, approval, extension, expiry): a
  missing helper made them crash – and that crash revealed which email addresses have an account. Mails now go out in
  the recipient's language, and the reset page answers equally fast for known and unknown addresses.
- **Login lockout of real users:** many failed logins against one name used to block everybody with that name for
  5 minutes, including the real owner. Now the owner keeps logging in from addresses that logged in successfully before.
- The login no longer reveals through its response time whether a user name exists.
- Internal folders (`bin`, `klang`, `i18n`) are no longer downloadable.
- Device settings have a size limit per device.
- **Reverse proxy confirmation:** if requests arrive from a private address with a forwarded client address, the admin
  overview asks once whether that is your reverse proxy. "Yes" trusts only that proxy, "No" ignores forwarded addresses
  from private senders – nobody can fake their address to get around the login lockout any more.
- **Setup from the home network without a code again:** the setup page recognises the home network more reliably
  (private addresses and IPv6 addresses from the server's own network) and asks for the code only via a proxy, tunnel,
  the Docker bridge or the internet – and says why. `EINRICHTUNG_CODE_IMMER=1` brings back "always ask".
- **Own reverb files (impulse responses):** a normal user can no longer overwrite someone else's file with the same name
  (the new one gets "(2)"); admins can still replace. Uploads must be real WAV files (format and data sections).

Downloads with Tidarr (and other SABnzbd look-alikes) – tested end to end against an emulated Tidarr, checked by two
independent reviewers:

- **Albums are no longer named after the Tidal ID:** a download folder called like the job ID gets the album title instead.
- **Files still being written are not copied half-finished:** import waits until nothing changed for 30 seconds
  (Tidarr writes ReplayGain tags after reporting "completed"); files with timestamps in the future don't block it.
- **Imports are atomic:** files are copied into a hidden folder first and moved into place in one step – a restart in
  the middle leaves no half album in the library (leftovers are cleaned up after 6 hours).
- **Jobs waiting behind others are no longer cancelled** after 30 minutes as long as the queue moves (Tidarr reports no
  speed) – at most 24 hours.
- Lower-case status, missing storage path, "completed" still in the queue, and jobs that vanish after a Tidarr restart
  while the files are there are all handled; a folder is never taken over by two jobs, and an old kept folder with the
  same name is not imported again.
- Search: the four quality variants of an album are all listed (hi-res first), AAC/M4A is recognised, `.lrc` lyrics are
  copied along; "320k" is detected as 320 kbit/s and "Live '96" is no longer read as a bitrate.

## 0.9.1-beta.2 – large libraries

Load test with a synthetic library (20,000 real files scanned, database multiplied to 100,000 tracks) on a real
MariaDB 11.4, plus independent reviews of the code and the migration system. Result: with MariaDB, Amberwave was already
fast at 100,000 tracks – lists, album pages and search answer in 10–200 ms. This release fixes the weak spots that
showed up anyway and makes updates of big databases safe.

- **Typo search** (only used when the normal search finds nothing) has a time budget: 2.1 s → 1.2 s at 100,000 tracks.
- **Artist pages** of artists with many albums: 0.18 s → 0.07 s (roles and collaborators are looked up from the artist).
- Album and artist lists, album pages: queries rewritten without per-row subqueries (same results, verified row by
  row) – this matters for databases that optimise less well than MariaDB.
- Going back to a list where you clicked "Load more" several times reloads it in **one request** instead of page by page.
- **Fewer background database writes:** technical updates (loudness, genres, popularity, artwork lookups) no longer mark
  albums as changed, genre families are only recalculated when something changed, the sound-analysis index is rebuilt
  far less often, and the scanner skips clean-up passes when nothing changed.
- Remote control: devices are woken by a small signal file instead of polling the database several times a second.
- Streaming closes its database connection before sending audio; the session lock is released early on read requests.
- PHP OPcache enabled in the Docker image; the schema check runs once per start instead of on every request.
- Player: the queue is saved less often and in a bounded window (very long queues no longer write megabytes on every
  track change).
- New indexes for large libraries (best file per track, play counts).
- Fixed: removing a track from a playlist could also remove it from a playlist you had opened earlier.
- Fixed: hidden admin panels kept refreshing at full speed in the background.
- `DB_PUFFER` (optional) sets the MariaDB buffer pool size in the compose files (default 512M).

Updates on big databases (from an independent review of the migration system):

- **Database updates run at container start**, before the web server – no longer inside the first page request,
  where time and memory limits could kill the pre-update backup on large libraries.
- **No parallel migrations:** if another process is still updating, others wait instead of starting the same
  changes a second time; the page shows "Update in progress" and reloads by itself.
- **The clean pre-update backup is kept:** exactly one backup per old schema version. A failed update no longer
  retries on every request (2-minute pause, clear message) and can't rotate that backup away.
- The backup streams rows instead of loading whole tables into memory (test with 100,000 tracks: about 1 MB of PHP memory).
- Schema changes give up after 20 s if a table is busy (e.g. a running scan) instead of blocking everything.
- Redundant indexes removed (less work for every scan); the scanner reads only the columns it needs.
- New manual GitHub workflow "Load test": real MariaDB, synthetic library, scan, 100,000 tracks, API timings.

Windows client:

- **Large tracks no longer fill the RAM:** a track bigger than 48 MB (hi-res, long classical works) is buffered in a
  temporary file instead of memory; the file is deleted automatically. Playback stays gapless and bit-perfect.

## 0.9.0-beta.2

  limit (20 per hour) only applies to browsers that have never signed in to that account.

- **Setup always asks for the setup code** (the link in the log contains it) – `EINRICHTUNG_CODE_IMMER=0` restores the old
  behaviour on the home network.
- Logs mask API keys, tokens and passwords. MusicBrainz & Co. now see the project URL as contact instead of a personal address.

Windows client:

## Before the beta (0.1 – 0.2.178)

The development history before the beta (it used to be part of the README).

### What v0.1 can do

- **Accounts** as in the book archive: registration with activation (1–24 months), renewal, blocking, expiry reminder,
  login lockout after failed attempts, “Remember device”, device limit, forgot password, email via web.de.
- **One folder = one album** as long as the album title is the same – even if the album artist is missing on individual
  files (previously they were split off as an invisible second edition). Files with no counterpart in a matched edition
  (bonus tracks, demos) appear as additional tracks. Under Administration → Library → Anomalies you will find files
  that only exist in editions that are not displayed.
- **Scanning** without prompts: FLAC, MP3, M4A/ALAC, Opus, OGG, WAV, AIFF, WavPack and more; CD1/CD2 subfolders,
  compilations, multiple artists from the tags (ARTISTS), cover from the folder or the file, ReplayGain, incremental.
- **MusicBrainz matching**: all editions of an album (not just the first hits), filter by country/format/track count,
  “your file ↔ MusicBrainz” comparison line by line, import of album, edition, tracks, artist credits,
  label, genres, producers, musicians with instruments, songwriters (via compositions), technical details; band members.
  Locked fields remain untouched.
- **Editing directly in the library** (admin only): “Edit” button on the album page (on mobile in the ⋯ menu) for album,
  track list (title, disc and track numbers; a new disc number = a new disc, duplicate assignments are rejected),
  contributors, edition, cover and album artists; “Edit track …” in the ⋯ menu of each track (name, disc and number,
  separate artists such as “feat.” – the guest then also appears on their artist page); “Edit” on every artist page.
  Anything changed by hand is automatically protected from scans and MusicBrainz.
- **Albums grouped “By artist”** (toggle at the top right, with A–Z bar) and **sortable artists**
  (name A–Z/Z–A, most albums, recently added, most listened to by you, random; filter people/bands).
- **Family sees one edition per album** (the one with the most tracks, the newest in case of a tie; changeable by you).
- **Interface** in a glass design with an amber accent: Home (Continue listening, New, Frequently played, Discover), albums with filters,
  album page with contributors, artist and person pages (As producer / musician / songwriter, frequent partners, lineup),
  search, playlists (also shared with the family), Bookmarked, History, Profile. Fixed layouts for desktop, tablet and mobile
  (tab bar at the bottom).
- **Player** without interruption while navigating. “Now playing” in the “Stage” layout: on desktop, cover in the center of the screen, contributors on the left, Up next on the right,
  at the bottom signal path | controls (centered) | quality + volume – all without scrolling. On mobile only the player,
  Up next / contributors / technical details in a sheet from below,
  lock screen controls. Volume leveling according to EBU R128 (see below). Streaming as original or converted live (Opus 256/160/128, AAC as fallback).
- **API-first**: The interface uses `/api/v1` exclusively. The future Windows player logs in with a device key
  and receives the files bit-perfect (see `docs/API.md`).

- **Artist images from fanart.tv**: Enter the key under Settings, and the app fetches the images in the background
  (every `FANART_ALLE_MINUTEN`, default 10) or immediately via Administration → Library → “Fetch now”. Artists without a
  MusicBrainz ID are looked up unambiguously beforehand; images you upload yourself are kept.
- **Names always “First name Last name”**: “Jackson, Michael” from the tags becomes “Michael Jackson”
  – duplicate artists are merged in the process. Band names such as “Earth, Wind & Fire” stay as they are.
  Sorting is also by first name last name (“Michael Jackson” under M); a leading article does not count
  (“The Beatles” under B, can be disabled with `SORTIERUNG_OHNE_ARTIKEL=0`).

- **Quality at home / on the go, remembered per device**: On the home network (directly on the LAN or through the tunnel with your own
  public address), “Automatic” plays the original file, provided the browser can handle it. On the go: phone/tablet
  (by browser identification) Opus 160, on mobile data or with data saving Opus 128, otherwise Opus 256. Both settings
  are stored per device on the server; a network change takes effect from the next track.

- **Robust scanner**: Folders/files without read permission are reported (Administration → Library) instead of being silently skipped,
  and whatever of them had already been scanned is kept. If the music folder is empty (array stopped, mount missing),
  nothing is deleted. The app runs as `PUID`/`PGID` (Unraid: 99/100 like Lidarr) and can therefore read everything Lidarr creates.

- **Artist page: genres and most popular tracks**: Genre badges from MusicBrainz (the top five by votes, otherwise the
  most frequent genres of their albums in the collection; clicking shows all albums of the genre). Below that, the **top 10 worldwide** by
  listeners on ListenBrainz (open statistics from MetaBrainz, no key required, refetched every `BELIEBT_TAGE`) – matched
  via the MusicBrainz recording, otherwise via the title without suffixes such as “Remaster”; the version from the
  studio album is played. **Missing tracks stay in the list**, dimmed, with the album they appeared on, and a
  summary (“6 of the top 10 are missing from your collection – found on: Bad (2), …”). **Ours** toggle: the most-listened tracks
  of all family members. “Play available” plays only what is there.

- **Clean up files** (Administration → Library or album menu “Clean up files …”, matched albums only):
  writes the data from Amberwave into the files – FLAC (Vorbis comment), MP3 (ID3v2.4) and M4A (iTunes fields) with
  the field names of MusicBrainz Picard: title, artists individually and as display text, multiple album artists,
  edition (label, catalog number, barcode, country, medium, date/original release, version name), genres, composer,
  lyricist, producer, mix, engineer, musicians with instrument, work, all MusicBrainz IDs and ReplayGain from the app's own
  loudness measurement – plus the cover. Old and foreign tags are cleaned up in the process (`AUFRAEUMEN_TAGS=sauber`); only
  `AUFRAEUMEN_BEHALTEN` (lyrics, ISRC) and technical data for gapless playback (iTunSMPB) remain. The preview shows
  for each field previous → new or “will be removed”. Nothing ever happens on its own:
  first the preview, then your approval (per album or all at once). Renaming and tagging happens in place in the
  library's root folder, e.g. `Bruno Mars/2012 - Unorthodox Jukebox/01 - …` (old files go to the recycle bin).
  The audio is never touched: if everything fits into the existing header (padding block), only that is overwritten, otherwise
  the file is reassembled alongside; before and after, a checksum is computed over the decoded audio data –
  if they differ, the file stays as it was. Also: naming folders and files by pattern
  (`AUFRAEUMEN_ORDNER`, `AUFRAEUMEN_DATEI`, default `Albumartist/Year of the edition - Album (Edition)/01 - Title`, with multiple discs `…/CD 2/01 - Title`
  (`AUFRAEUMEN_CD_IMMER=1`: disc folder even with only one disc);
  disc numbers from MusicBrainz, even with only one disc; names are Windows/SMB-safe, `AUFRAEUMEN_ZEICHEN=ascii` strict ASCII; booklets & co. move along) and removing junk (.nfo, .sfv, .m3u, .log, .cue,
  Thumbs.db …). **Always preview first** (per album: new names, tag changes field by field, notes such as
  missing write permissions or folders that also contain other albums), only approved items are executed, in the background
  and never at the same time as scanning. Deleted items and the old tags (as JSON per file) end up in the folder
  `.amberwave-papierkorb` in the music folder and are deleted after `AUFRAEUMEN_PAPIERKORB_TAGE` (30). The database is
  updated right away (paths, sizes, tags) – no rescan needed, playback continues.

- **Recognize albums by sound** (Administration → Library): Each track gets an acoustic fingerprint
  (Chromaprint via the existing ffmpeg, the first 120 s, low priority), and AcoustID names the MusicBrainz recording for it.
  For each album folder, the releases that contain (almost) all tracks are loaded and compared track by track – recording,
  order, count, durations → confidence in %. Unambiguous results are applied automatically (like “Apply this edition”,
  an existing cover is kept). If the same track list exists on several editions, the MusicBrainz ID or barcode from
  the tags decides, then the durations, otherwise rules: official, format matching the files (CD or, for hi-res, Digital), country
  (DE, Europe, worldwide …), earliest date – these albums are listed for review, with all checked editions for
  comparing and switching. Only albums not yet matched are touched; the files are not changed in any way.
  Requires a free AcoustID key (Settings or `ACOUSTID_API_KEY`); `ERKENNUNG_AUTO=regeln|eindeutig|aus`,
  `ERKENNUNG_SCHWELLE` (90 %), `ERKENNUNG_PARALLEL`. Runs in the background (AcoustID ≤ 3, MusicBrainz 1 request per second).

- **Editions as separate albums**: Configurable per album under ⋯ → “Show editions …” – then, e.g., the original
  and the remaster appear side by side in all lists (with a small version label), without switching.
- **Interface**: custom select fields in the app style (on mobile with the system picker), back button between logo and navigation,
  play button at the bottom right on the cover, artist page grouped by type (albums, EPs, singles, live, compilations …).

- **Gapless playback** for live and concept albums, sample-accurate: At home every track is transmitted as
  FLAC (FLAC files bit-perfect, other formats decoded losslessly) and joined seamlessly; on the go, consecutive
  tracks of an album are encoded as one continuous Opus stream. The files remain unchanged.
  Can be disabled under Profile & Playback; browsers without Media Source Extensions automatically use the classic path.
  If a browser cannot handle FLAC as a stream (e.g. Chrome on Android) or the FLAC path causes problems, “Original” continues there gaplessly
  as Opus 256 instead of with pauses (switchable under Profile & Playback, with diagnostics of the device's capabilities).
  If the format changes between two tracks (sample rate, channels or bit depth, e.g. 44.1 kHz/16 bit → 48 kHz/24 bit),
  a fresh buffer begins – at that point there is a tiny gap, but no noise from
  a format change in the middle of the Media Source buffer.
- **Spatial audio (upmix stereo → 5.1/quad)**, only on a multichannel output (e.g. PC via HDMI to an AV receiver, set to 5.1 in Windows;
  on the receiver, play multichannel PCM directly). L/R stay bit-perfect and unchanged at the front; per frequency band, only what is uncorrelated between L and R
  (reverb, room, audience) goes to the rear – vocals and panned instruments
  stay at the front. Rear: no bass (high-pass), fewer low mids, somewhat darker, attacks damped with look-ahead,
  ducking by the front, early reflections with different delays and a dark room reverb that the
  direct sound (without bass) also excites slightly – this gives even dry recordings space. Presets **Subtle, Room, Hall, Live** under
  Profile & Playback or in the ⋯ menu of “Now playing”; **key U** toggles between Off and the preset while listening
  (A/B). For auditioning in the DAW: ⋯ → “Export track as 5.1 WAV” (all four presets, 24 bit, L R C LFE Ls Rs).
  **Real rooms for the reverb:** Under Administration → System, the server downloads the free “IM Reverbs” package from Voxengo at the push of a button
  (Musikverein, La Scala Milan, Salon …; © Aleksey Vaneev, not shipped
  with Amberwave, address via `RAUMKLANG_IR_URL`), and your own WAV impulse responses can be uploaded. The presets choose
  a suitable room automatically; in the profile, a specific one can be chosen per device. On pause/stop, the
  surrounds and reverb fade out immediately as well. **Intensity** (room/reverb: reverb ±12 dB, early reflections ±6 dB) and **surround level**
  (Ls/Rs ±12 dB) can be fine-tuned per device – the center is always the preset (Profile or Surround menu).
  **Center and bass management** (from 0.1.118): The front is decoded to L/C/R via M/S (center share 0–100 %, middle =
  classic matrix: the center gets M at 0 dB, the front keeps M at −3 dB). Bass below the crossover frequency (80/100/120 Hz,
  Linkwitz-Riley 24 dB/oct.) goes from L/C/R into the LFE (lowered by −10 dB because the receiver boosts the LFE by 10 dB; or 0 dB).
  Defaults `RAUMKLANG_CENTER_ANTEIL`, `RAUMKLANG_LFE_TRENNUNG`, `RAUMKLANG_LFE_PEGEL`. The spatial audio module restarts fresh on every track selection,
  every skip and every play (`RAUMKLANG_NEUSTART=0` turns this off); the “Fine-tune spatial audio” dialog shows which version is running.

- **Level meter** in the player bar and in “Now playing”: small peak level meters in dBFS (before the volume),
  2 channels, with active spatial audio 5.1 (L R | C LFE | Ls Rs) or quad; fall-back 20 dB/s, peak hold 1.5 s, red from
  0 dBFS. Runs via Web Audio (the volume then sits behind the measurement) – on at the desktop, off on mobile/tablet,
  can be disabled under Profile & Playback. Gapless remains sample-accurate via this path as well.

- **Equalizer** (remembered per device): low and high shelf and two bells, all fully parametric (frequency continuously variable,

#### Setting up direct access

1. In the compose file, under the `app` service in `ports:`, add a second line: `- "${APP_BIND:-0.0.0.0}:${LOKAL_HTTPS_PORT:-8443}:8443"`
   (a separate port next to the app port, e.g. 9950 for the app and 8443 for direct access)
   (home network only – nothing is forwarded in the router). `APP_URL` must be set in the .env. Apply the update
   and restart the stack once (the start script switches on HTTPS in the container).
2. At Cloudflare under My Profile → API Tokens, create a token with the template "Edit zone DNS" for your domain.
3. Administration → System → "Direct access on the home network": enter the token, check the name (suggestion `lokal.<your app address>`)
   and the IP of the Unraid on the home network, "Set up". Afterwards reload the page once.
4. The first time, Chrome may ask whether the site may access devices on the local network – allow it.
   If the router has DNS rebind protection, add the name there as an exception.

If it does not work, "Check from this device" shows the cause: page not yet reloaded, network/DNS/port/certificate,
`APP_URL` does not match the address being accessed, or Chrome is blocking access to the local network. The direct address
also works if the app is opened on the home network via the server IP (e.g. `http://192.168.1.10:9950`).

If you prefer to use your own reverse proxy: `DIREKT_URL=https://…` in the .env fixes the direct address
(without the automatic certificate handling).

- **Gear icon and Scan button** (0.2.177): At the top right next to the profile, a gear icon leads directly to the settings. In Administration → Library, “Scan” now permanently sits next to the heading – reads in new and changed files and shows the progress meanwhile (“Scanning … 42%”).
- **Filter download search by source** (0.2.178): If several indexers return results, the line “Source” appears below the results header with each indexer and its result count – one click shows only its releases (click again or “All” removes the filter). Merged releases count for every indexer where they are listed. Can be combined with the quality filter.
- **Windows Client 0.8.6:** The first track after startup begins immediately. If the ASIO driver is already running at the matching rate (e.g. fixed 96 kHz), the startup check and “pause after rate change” are skipped. Both now apply only when the driver is actually switched.
